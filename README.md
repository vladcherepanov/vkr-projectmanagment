# Управление проектами и задачами

Простой планировщик в браузере. Можно создавать проекты, добавлять и редактировать задачи, назначать приоритет и срок, отмечать выполнение. Задачи с прошедшим сроком выделяются в списке.

## Запуск

Откройте `index.html`. Устанавливать пакеты и собирать проект не нужно.

Лучше открывать приложение через локальный HTTP-сервер, например из редактора: при запуске через `file://` работа хранилища зависит от браузера.

## Файлы

- `index.html` — интерфейс.
- `styles.css` — стили и адаптивная верстка.
- `app.js` — работа с проектами, задачами и хранилищем.
- `index.test.cjs` — тесты.

## Данные

Проекты сохраняются в `localStorage` под ключом `pmAppState`. Они доступны только в том браузере и по тому адресу, где были созданы. Сервера, учетных записей и синхронизации нет. При первом запуске показываются два примера проектов.

Для резервной копии есть экспорт в JSON. Импорт заменяет все текущие проекты после подтверждения. Если файл содержит ошибки или не удалось записать его в хранилище, текущие данные остаются на месте.

Если сохраненная запись повреждена, приложение не затирает ее и отключает автосохранение. Можно импортировать корректную копию для восстановления. При ошибке сохранения экспортируйте текущие данные перед закрытием страницы: несохраненные изменения останутся только в памяти.

Срок задачи задается датой без времени. Задача считается просроченной со следующего дня по местному времени браузера, если она еще не выполнена. Подсветка обновляется при действиях пользователя и смене дня; в фоновой вкладке возможна задержка.

### Формат резервной копии

```json
{
  "projects": [
    {
      "id": 1,
      "name": "Мой проект",
      "tasks": [
        {
          "id": 101,
          "text": "Подготовить отчет",
          "done": false,
          "priority": "medium",
          "dueDate": "2026-12-31"
        }
      ]
    }
  ],
  "currentProjectId": 1
}
```

Приоритет: `high`, `medium` или `low`. Если срока нет, `dueDate` равен `null`. Старые файлы без этого поля тоже поддерживаются. Дата должна существовать и иметь формат `YYYY-MM-DD`, год — от 0001 до 9999.

ID — положительные безопасные целые числа. ID проектов не повторяются, ID задач уникальны внутри проекта. Названия проектов не должны совпадать без учета регистра и крайних пробелов. У каждого проекта нужен массив `tasks`; пустой список проектов допустим. Если выбранного проекта больше нет, выбирается первый.

Ограничения: название проекта до 40 символов, текст задачи до 100, не более 100 проектов и 10000 задач. Импорт принимает файлы до 8 МБ, но доступное место в `localStorage` может быть меньше.

## Проверка

Для тестов нужен Node.js 22 или новее:

```sh
node --test index.test.cjs
```

Тесты проверяют операции с задачами, сортировку, сроки, импорт и ошибки хранилища. Вместо браузера используется DOM-дублер, поэтому внешний вид, календарь и поведение диалога нужно проверять вручную.

Для быстрой проверки добавьте задачи со сроками вчера, сегодня и завтра, отредактируйте одну из них, затем перезагрузите страницу. Проверьте экспорт и повторный импорт. Просроченной должна быть только вчерашняя невыполненная задача.
